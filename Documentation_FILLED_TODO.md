# I. Project Overview
## 1.1 System Title
**RockStay - Hotel Management System**

## 1.2 System Description
This system is a Tkinter-based hotel management application that supports user authentication, room availability viewing, booking/confirmation, and an admin dashboard for managing reservations and room status. It uses a local SQLite database to store users, rooms, and rental/booking transactions.

## 1.3 Objectives
- Provide a desktop UI for booking hotel rooms and tracking reservation status.
- Provide admin tools to manage rooms (Available/Occupied/Maintenance), approve bookings, and handle check-in/check-out.
- Use SQLite persistence and structured code layers (Views → Controllers → Services → Repositories/Models).

## 1.4 Scope and Limitations
**Scope (implemented in repo):**
- Login and Signup
- User Dashboard: show bookings + view available rooms + confirm reservation
- User Settings: profile update + change password
- Admin Dashboard: Home/Rooms/Booking/Check-in-Out/Billing/Guest/Settings (via sidebar navigation)
- Map screen (floor images) for visual browsing

**Limitations / gaps (based on code):**
- No real payment gateway integration (payment is simulated via status flags like `unpaid/paid/approved`).
- Some admin modules referenced by the main admin dashboard appear to be under-construction (e.g., “Reports” route exists but `create_reports` is not defined in the provided file context).

# III. System Features
## Feature List
# | Feature Name | Description
---|---|---
1 | Login / Role-based access | Users log in using email/password; redirects to user dashboard or admin dashboard depending on role.
2 | Signup (Role selection) | New accounts are created with role (user/admin preset by caller) and validated input.

# V. Explanation of Important Code Parts
## 5.1 Code Snippet 1 — Role-based navigation at login
**Purpose:** After a successful login, the system redirects users to the correct dashboard based on `role`.

**File:** `views/pages/authentication/login.py` (function: `submit_login`)

**Key logic:**
- Uses `UserController.handle_login(email, password)`
- If `role == "admin"` → `app.show_admin_admin_dashboard(admin_id=...)`
- If `role == "user"` → `app.show_user_dashboard(user_id=...)`

## 5.2 Code Snippet 2 — Booking confirmation flow
**Purpose:** User selects an available room and confirms booking; total price is computed and reservation is created.

**Files:**
- `views/components/user/booking_form.py` (function `handle_booking` + price preview)
- `controllers/rental_controller.py` (function `handle_confirm_booking`)
- `services/rental_service.py` (function `confirm_booking`)
- `models/RentalModel.py` (function `create_reservation`)

**Key logic:**
- Price preview: `price_per_night * nights`
- Calls `RentalController.handle_confirm_booking(... payment_status="paid")`
- Repository/model inserts booking in SQLite and updates room status to `Occupied` when active.

## 5.3 Code Snippet 3 — Admin listing + approval/check-in/out
**Purpose:** Admin sees booking cards grouped by payment/status and can approve/check-in/check-out.

**File:** `views/components/admin/reservation.py`
- Creates panels: “Ongoing Bookings”, “Upcoming Reservations”, “For Approval (Paid)”
- Chooses target panel based on `payment_status` and `status`
- Buttons call:
  - `RentalController.handle_approve_booking(rental_id=...)`
  - `RentalController.handle_cancel_booking(rental_id=...)`
